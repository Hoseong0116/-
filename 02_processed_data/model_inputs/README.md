# S0·S1 모델 입력 점검 및 팀 파일 병합 기준

점검일: 2026-09-18. `03_scripts/model_inputs/prepare_model_inputs.py` 실행으로 이 폴더의 CSV와 `audit_summary.json`을 재생성한다. `01_raw_data`와 기존 `02_processed_data`의 원본·선행 가공 파일은 변경하지 않는다. CSV는 UTF-8 BOM이며 결측은 빈 필드다. Python에서는 `utf-8-sig`로 읽어야 한다. 일부 선행 파일은 헤더에 BOM이 두 번 있어 병합할 때 헤더 선두의 `\ufeff`를 제거해야 한다.

## 즉시 사용 가능한 범위

| 파일 | 단위 / 확보 내용 | 사용 범위와 제한 |
|---|---|---|
| `scenario_core.csv` | 시나리오 2행 | S0는 UD 차량별 월 완료 100건 우선, S1은 100건 의무 미적용. UD 12대 동일. 30분 재평가는 S1의 초기 연구설정. 기존 차량 854대는 **2025년 수치의 2026년 유지 가정**이며 실측 2026년 대수가 아님. |
| `pv5_vehicle_inputs.csv` | PV5 WAV 제원 1행 | 2027년형 Basic Long Range 대표 제원의 공인 배터리 정격 71.2kWh·전비 4.4km/kWh·시험 충전시간. 실제 UD 12대의 세부 트림 일치 여부, 사용가능 용량과 최대 수전출력은 미확인. 정격용량으로 SOC를 정확히 계산할 수 없음. |
| `charger_inventory_prepared.csv` | 원자료 충전기 433행 | 출처 행·원래 충전기 ID, 서울 여부, 커넥터 표기, 정격출력, 단독/동시 표기, 평일/주말 개방 시각을 분 단위로 정리. **427행은 조사 후보**. 실제 가용 충전기 확정 목록이 아님. |
| `carbon_factors_review.csv` | 대표 계수 9행 | 단위·적용연도와 옛 대리값 승인 필요 여부를 표시. 2023년 전력계수와 구형 차종 인증값을 최종 계산에 자동 투입하지 않음. |
| `model_readiness.csv` | 필수 입력 11종 | 각 입력의 준비 상태와 수령할 자료를 명시. |

원 충전기 433행 중 서울 밖 4행, AC3상 단독 1행, 충전기 타입과 출력분류가 충돌하는 1행을 제외하면 서울 소재 조사 후보가 427행이다. 원 데이터의 `운영기관=서울시`는 소유·관리 표시이며 실제 충전사업자·요금표 키로 사용하지 않는다. `동시` 표기는 전력공유 가능성만 뜻하며 각 커넥터가 언제나 정격출력을 낸다는 뜻이 아니다. `AC완속`은 물리 커넥터 규격 미표시로 현장 호환성을 확인해야 한다. `이용가능시간`은 공개시간일 뿐 실제 가동·대기·주차 진입 가능성을 증명하지 않는다. 24시간 표기는 374행, 시간제약 표기는 59행이다. 평일 전용 시설은 주말 시각을 공란으로 유지한다. 공휴일 운영규칙과 원 충전소 목록의 실제 갱신일은 원자료에 없어 추가 확인이 필요하다.

`electricity_price_by_operator.csv`의 505행은 101개 사업자 × 5출력구간의 **회원 공시요금**이다. 충전기 433행에는 실제 운영사업자 정보가 없어 둘을 정확히 연결할 수 없다. 실제 청구액 산출에는 세션별 kWh·결제액·회원/로밍/계약유형이 필요하다. 서울시 소유 충전기라는 이유로 서울시 공시단가를 일괄 적용하지 않는다.

현재 `01_raw_data/disabled_taxi`, `01_raw_data/general_taxi`, `01_raw_data/spatial`에는 분석 원자료가 없고, UD 파일은 12개 빈 입력행을 가진 템플릿이다. `taxi_revenue_hourly.csv`도 48개 시간 슬롯에 관측 매출·건수·공차 데이터가 전부 비어 있다. 따라서 수요예측 훈련, S0 실적 보정, 일반영업 수익성 비교의 **최종 실행은 아직 불가**하다. 공개 운임표는 승객별 실제 매출 또는 차량시간당 벌이를 대신하지 못한다.

## 다른 팀원 파일 수령 시 연결 규칙

파일을 `01_raw_data`의 해당 하위 폴더에 원본 그대로 보관하고, 출처기관·관측기간·수집일·시간대(Asia/Seoul)·단위·데이터 사전을 함께 받는다. 개인정보는 비식별 ID로 받는다. 팀 자료가 도착하면 새 전처리 파일을 별도 저장하고, 이 폴더의 표준 키로 연결한다.

| 자료 | 최소 필드 | 기본 키 / 주의점 |
|---|---|---|
| 장애인 호출·배차 | `request_id`, 호출·배차·차량도착·승차·하차 시각, 출발·도착 행정동 코드, 취소/미배차 상태, 배차 차량 ID | `request_id`; 여러 이벤트행이면 `request_id + event_type + event_timestamp`. 시간순 중복 제거, 취소건 처리와 대기시간 정의를 고정. 행정동 × 시간 집계 시 실제 0건과 자료 누락을 구분. |
| 행정동 코드·경계 | 2025 기준 행정동 코드, 유효 시작·종료일, 경계 또는 좌표 | `행정동 코드 + 유효기간`; 개편된 동을 현재 코드로 무조건 치환하지 않음. |
| 차량·근무 로스터 | 차량 ID, 차종·연료, 가동일/근무 시작·끝, 출발·복귀 위치, 초기 SOC(UD) | `vehicle_id + duty_date/shift_id`; 854대 집계행을 854개의 관측 차량행으로 복제하지 않음. |
| 시간대별 OD | 출발·도착 행정동 코드, 유효일/시간대, 이동시간·거리 | `origin_admd_cd + destination_admd_cd + time_band + effective_period`; 거리와 시간 단위 통일, 비서울 통행 따로 기록. |
| UD 운행·충전·정산 | 차량 ID, 이벤트/운행 ID, 시각, 장애인/일반 구분, 거리, 승객운임, 운영사 수입·보조금, 충전소 ID, kWh·결제액·SOC | `vehicle_id + event_id`, 일별 집계라면 `vehicle_id + date`; 100건 완료시점과 월 경계 계산. 승객운임과 보조금 차액정산의 중복계상 방지. |
| 일반택시 영업 | 연월·요일/공휴일·시간·행정동, 건수, 운임합계, 유상/공차거리·시간, 영업가능 차량시간 | `period + day_type + hour + admd_cd`; 시간당 매출 = 운임합계/영업가능 차량시간. 지역을 뺀 서울 전체 시간대 자료로 지역별 기회비용을 만들지 않음. |
| 충전소 보강 | 충전기 ID, 좌표, 실제 사업자, 커넥터 규격, 정격/공유출력, 최신 가동상태, 높이·폭·기계식 여부, 접근제한, 실제 이용요금 | 원본의 `충전소명 + 충전기ID`와 매칭 검증. 단순 충전소 이름만으로 여러 기를 1기로 축약하지 않음. |

## 병합 전 확인할 충돌

1. `fleet_master.csv`의 공식 2025년 854대와 출처 미확인 2026년 691대·126대는 분모·대상범위가 다를 수 있다. 두 값을 합쳐 2026년 전체 차량수로 확정하지 않는다.
2. `carbon_factor_master.csv`의 2023년 전력계수, 2020~2023년 차종 인증 대리계수, 동일가중 3차종 평균 0.177kgCO2/km는 최신 서울 실제 차량 구성·실연비가 아니다. 오래된 수치를 적용해야 한다면 사용자 승인 후 민감도 분석으로 사용한다.
3. 연료계수의 `kgCO2/L`와 전력계수의 `kgCO2e/kWh`는 온실가스 범위가 다르다. 총 `CO2e`로 합치기 전 CH4·N2O 포함 범위와 전력 사용량 측정경계를 통일한다.
4. 2026-09-16의 LPG·경유 가격은 하루 평균이다. 2025 수요·운행기간에 대해 기준가격 분석으로 쓸지, 해당 기간 가격을 다시 구할지 명시한다.
5. 서울 중형택시 운임은 2023년 시행이지만 2026-04-03 갱신 공식 페이지에서 현행임을 확인했다. 과거 관측 매출자료의 가격연도와는 구분한다.
6. 파일이 존재한다는 것과 계산 가능한 관측값이 있다는 것은 다르다. `status`와 결측률, 키 유일성, 날짜범위, 서울 필터, 차량수·건수 합계를 확인한 뒤 시뮬레이션에 연결한다.

모든 모델 실행은 S0/S1에 동일 수요·차량·OD·시드·분석기간을 사용한다. 임시 가정은 작동 시험에만 사용하고 최종 정책효과 또는 수익률로 보고하지 않는다.
