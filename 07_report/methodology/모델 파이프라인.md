# 수요예측 및 통합 동적운영 시뮬레이션 모델 설계

## 1. 전체 연구 모델 구조

연구의 전체 분석 흐름은 다음과 같이 구성한다.

```
2025 서울시 장애인콜택시 약 150만 건
        ↓
데이터 전처리 및 시공간 수요 분석
        ↓
ST-MGCN 기반 행정동별 수요예측
        ↓
미래 장애인 수요 예측값
        ↓
장애인콜택시 + UD택시 통합 운영 시뮬레이션
        ↓
장애인 배차 / 일반영업 / 충전 / 재배치 / 대기
        ↓
S0 현행 운영 vs S1 통합 동적운영
        ↓
서비스·탄소·비용·수익 비교
```

연구에서 **수요예측 모델과 시뮬레이션 모델의 역할은 구분**한다.

- **수요예측 모델:** 앞으로 어느 지역에서 장애인 호출이 발생할지 예측
- **시뮬레이션 모델:** 예측된 수요를 이용해 차량을 어떻게 운영할지 결정
- **최종 검증:** 예측 정확도 자체보다 실제 대기시간·탄소·비용 개선 여부 평가

# 2. 수요예측 모델

## 2.1 모델 선정

### ST-MGCN

**Spatiotemporal Multi-Graph Convolution Network**

단순 GCN이 아니라 **공간적 관계 + 시간적 관계를 동시에 고려하는 그래프 기반 딥러닝 모델**을 사용한다.

선행연구에서는 서울시 장애인콜택시 행정동별 수요예측에 ST-MGCN을 사용했다. 행정동을 노드로 두고 여러 종류의 관계를 그래프로 구성한 뒤 GCN으로 공간 특성을 학습하고, 시간적 특성은 CGRNN 계열 구조로 반영했다.

---

## 2.2 ST-MGCN을 사용하는 이유

장애인콜택시 수요는 단순히 한 지역의 과거 수요만으로 결정되지 않는다.

예를 들어:

- 인접 지역 수요
- 도로 연결성
- 병원·재활시설 분포
- 장애인 관련 시설
- 차고지 위치
- 주변 차량 공급
- 시간대

등이 함께 영향을 미칠 수 있다.

따라서 일반적인 시계열 모델보다 **서울 행정동 간 공간관계를 함께 학습할 수 있는 GCN 계열 모델이 적합**하다.

선행연구에서도 장애인콜택시 수요의 공간관계를 여러 그래프로 구성하고, 다중 그래프를 사용했을 때 그렇지 않은 경우보다 RMSE 성능이 개선된 것으로 보고했다. 딥러닝을 활용한 서울시 행정동별 장애인콜택시 수요예측 방법 연구.pdf.pdfPDF

# 3. 그래프 구조

## Node

서울시 **행정동**을 하나의 노드로 설정.

선행연구는 2019년 서울시 행정동 424개 중 수요가 없던 1개 동을 제외하고 **423개 행정동**을 사용했다.

우리 연구에서는 **2025년 행정동 체계 기준으로 다시 구축**해야 한다.

---

## Edge

행정동 간 관계를 여러 개의 그래프로 구축한다.

### Graph 1. 공간 인접성

행정동이 서로 인접하는지 여부.

```
인접 = 1
비인접 = 0
```

선행연구에서는 주변 8개 행정동을 기준으로 공간 인접관계를 구성했다.

---

### Graph 2. 도로 연결성

행정동 간 실제 도로 이동거리 또는 이동시간을 이용한다.

단순 직선거리보다

> **실제 차량이 이동 가능한 도로 기준 거리**
> 

가 더 적절하다.

선행연구 역시 행정동 간 탐색거리를 이용해 Transportation Connectivity를 구성했다.

우리 연구에서는 가능하면

```
시간대별 OD 이동시간
```

까지 사용한다.

---

### Graph 3. 기능적 유사성

행정동 간 사회·시설 특성이 비슷한지를 그래프로 구성한다.

선행연구에서 활용한 변수:

- 의료 LQ
- 장애 LQ
- 차고지 여부
- 유동차량 대수

이 변수들로 행정동 간 cosine similarity를 계산했다.

우리 연구에서는 확보 가능 여부에 따라 다음을 고려한다.

```
의료시설
재활시설
장애인 관련 시설
장애인 인구
차고지 여부
장애인콜택시 공급
```

# 6. 수요예측 비교모델

ST-MGCN만 돌리지 않고 baseline을 두는 것이 필요하다.

### Baseline 1

Historical Average

```
요일 × 시간 × 행정동 평균수요
```

### Baseline 2

LightGBM

일반 머신러닝 기반 수요예측.

### Proposed Model

ST-MGCN

가능하면 세 모델을 비교한다.

평가지표:

```
MAE
RMSE
MAPE
```

단, MAPE는 수요가 0에 가까운 행정동이 많으면 불안정할 수 있으므로 **MAE/RMSE 중심**으로 평가.

# 7. 데이터 학습·검증 분리

Random Split은 사용하지 않는 것이 좋다.

미래 수요를 예측하는 문제이므로 **시간순 분할**을 사용한다.

예시:

```
1~8월    Train
9~10월   Validation
11~12월  Test
```

이렇게 하면 미래 데이터가 과거 학습데이터에 들어가는 **Data Leakage**를 방지할 수 있다.

# 8. 시뮬레이션 모델

## 모델 형태

### Discrete Event Simulation

**이산사건 시뮬레이션(DES)**

시간을 1초 단위로 계속 계산하는 것이 아니라 중요한 사건이 발생할 때 차량 상태를 갱신한다.

```

08:07 차량 충전 시작

08:25 승차
08:50 하차
```

장애인콜택시 운영은 호출·배차·승하차·충전 같은 이벤트 중심이므로 DES가 적합하다.

# 12. 동적 운영 방식

## Rolling Horizon

한 번 하루 전체 운영계획을 만드는 것이 아니라 일정 시간마다 미래 수요를 다시 예측하고 운영계획을 수정한다.

예:

```
현재 13:00
        ↓
ST-MGCN
13~14시 행정동별 예상수요
        ↓
차량 상태 확인
        ↓
배차 / 충전 / 재배치 / 일반영업 결정
        ↓
13:30
        ↓
새로운 실제 호출 + 새로운 예측
        ↓
운영계획 재계산
```

초기 후보:

```
10분
15분
30분
```

중 하나.

처음 구현은 **30분 Rolling Horizon**으로 시작하고 이후 민감도 분석 가능.

# 14. 배차 Cost Function

호출 \(j\)와 차량 \(i\)의 배차 비용을 계산한다.

기본 구조:

\[
Cost_{ij}
=
\alpha T_{pickup}
+
\beta D_{pickup}
+
\gamma SOC_{risk}
+
\delta ServicePenalty
+
\epsilon OpportunityCost
\]

구성요소:

### Pickup Time

승객에게 도착하는 예상시간.

### Pickup Distance

공차 이동거리.

### SOC Risk

배차 후 배터리 부족 위험.

기존 ICE 차량에는 적용하지 않음.

### Service Penalty

대기시간이 긴 지역이나 서비스 수준이 낮은 지역에 가중치를 부여.

### Opportunity Cost

UD택시가 장애인 호출을 수행할 때 포기하는 일반택시 영업 기대수익.

---

# 15. 차량-호출 Matching

초기 구현 후보:

### 최소비용 배차

각 호출에 가장 적합한 차량 선택.

### Hungarian Algorithm

동시에 여러 호출과 여러 차량을 매칭해야 할 경우 사용.

```
차량 20대
호출 15건
        ↓
Cost Matrix
        ↓
Hungarian Algorithm
        ↓
전체 비용 최소 차량-호출 조합
```

추후 OR-Tools 등을 사용할 수 있다.

# 17. UD 충전 모델

UD는 EV이므로 SOC를 차량 상태로 관리한다.

기본식:

\[
SOC_{t+1}
=
SOC_t
-
\frac{주행거리}{전비 \times 배터리용량}
\]

충전 시:

\[
SOC_{after}
=
SOC_{before}
+
충전전력량 / 배터리용량
\]

실제 계산에서는 충전효율 보정 가능.

# 21. 추가 시나리오가 필요할 경우

차량 증차 시나리오는 사용하지 않는다.

대신 모델 구성요소의 효과를 확인하는 방식으로 추가 가능.

### S0

현행 월 100건

### S1

수요 기반 통합배차

### S2

수요 + 위치 + 재배치

### S3

수요 + 위치 + SOC + 충전 + 일반영업

이 경우 각 기능이 결과에 얼마나 영향을 미치는지 **Ablation Analysis**가 가능하다.

# 24. 가장 중요한 실험 원칙

S0와 S1에는 반드시 **동일한 조건**을 넣는다.

```

동일한 OD 이동시간
동일한 기상조건
```

변경하는 것은 **운영정책만**이다.

그래야

> S1에서 대기시간이 감소한 이유가 증차가 아니라 운영정책 개선 때문이다.
> 

라고 주장할 수 있다.

# 26. SUMO를 사용하지 않는 이유

SUMO는

- 개별 도로
- 차량
- 신호
- 교차로

까지 시뮬레이션하는 미시교통 시뮬레이터다.

우리 연구의 핵심은 도로교통류가 아니라

> **장애인콜택시와 UD택시의 운영정책**
> 

이므로 과도하게 복잡하다.

따라서:

```
행정동 A → B
시간대별 이동시간
```

형태의 OD 이동시간 Matrix를 사용한 DES가 더 적합하다.

# 27. 강화학습을 우선 사용하지 않는 이유

강화학습으로도

```
배차
충전
재배치
일반영업
```

을 결정할 수 있다.

하지만 정책 공모전에서는

> 왜 이 행동을 선택했는가?
> 

를 설명하기 어려울 가능성이 있다.

따라서 초기 연구에서는:

> **ST-MGCN + Rolling Horizon + 최적화 기반 배차**
> 

를 사용한다.

향후 연구에서 RL 적용 가능.
